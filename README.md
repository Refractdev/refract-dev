# Refract

**Transform AI-generated code into maintainable, production-ready software.**

Refract is a code analysis and refactoring pipeline that bridges the gap between rapid AI-assisted prototyping and production-grade software quality. It analyzes codebases generated by tools like Lovable, Bolt, and Cursor, identifies structural issues, and provides actionable suggestions to eliminate comprehension debt.

---

## Introduction

AI coding tools have made it trivially fast to generate functional code. But speed comes at a cost: AI-generated codebases accumulate "comprehension debt" — code that works but is difficult to understand, maintain, or extend. Modules grow oversized, types devolve to `any`, dependencies tangle into cycles, and documentation falls behind.

Refract solves this. It is an AST-powered analysis engine that inspects your codebase, detects patterns of poor maintainability, and surfaces prioritized, actionable refactoring suggestions. For Pro and Team users, it can automate the entire refactoring workflow — generating pull requests with documented changes, updated documentation, and clean code structure — all while preserving the original behavior.

---

## How It Works

1. **Connect** — Link a GitHub or GitLab repository and select a branch to analyze.
2. **Parse** — Refract clones or fetches the repository contents and parses every file into an Abstract Syntax Tree (AST) using Babel.
3. **Analyze** — A suite of detectors walks the AST looking for specific issues: `any` type usage, oversized components, dead state, circular dependencies, missing error boundaries, and more.
4. **Suggest** — Each issue is enriched with impact, effort, blast radius, and a suggested fix. Results are presented in a prioritized list with before/after code previews.
5. **Refactor** — Users review suggestions individually or in batch. Pro/Team users can auto-generate a pull request with all accepted changes applied.
6. **Document** — Refract can generate or update README files, API docs, and architecture overviews automatically.

The engine runs entirely in Web Workers for performance, with all parsing, detection, and enrichment happening client-side for privacy and speed.

## Core Features

### Code Analysis Engine
- **AST-based Parsing** — Uses `@babel/parser` with full TypeScript, JSX, and modern ECMAScript support. Produces a unified node format shared across analysis and transformation pipelines.
- **Detector Suite** — 15+ built-in detectors covering: any-type usage, oversized components, dead state, missing documentation, console.log leaks, effect missing deps, prop drilling, generic naming, circular dependencies, state explosion, API calls in components, missing error boundaries, memory leaks, duplicate logic, and unsafe casts.
- **Cross-file Analysis** — Detects circular dependencies and duplicate logic across file boundaries using a shared import map.
- **Circular Dependency Detection** — Uses DFS with cycle detection on the full import graph, reported as `circular-dep` issues.
- **Import Map** — Builds a dependency graph from import declarations, resolving relative paths across the project.

### Issue System
- **Prioritization** — Each issue is scored by a formula: `priority = (impact × 10 + blastRadius) / effort`, where impact is High/Medium/Low, blast radius is the in-degree of the file in the import graph, and effort is low/medium/high.
- **Categories** — Issues are classified into 15 distinct categories with consistent IDs and metadata.
- **Patches** — Each issue carries a before/after patch for direct application.

### Refactoring Suggestions
- Per-issue before/after code previews
- Individual or batch acceptance
- Impact and effort estimation
- Priority-based ordering

### Auto-Refract (Pro/Team)
- Direct pull request generation with documented changes
- Automatic changelog creation
- Batch processing of multiple suggestions
- Conflict resolution assistance

### Documentation Generation
- Automatic README creation and updates
- Function and module-level documentation

### Code Quality Dashboard
- Health scores (0–100) per project
- Trend tracking over time
- Drill-down into specific issues by file

## Typical Workflow

1. **Sign in** via GitHub or GitLab OAuth.
2. **Select a repository** from your account and choose a branch (defaults to main/master).
3. **Run analysis** — Refract scans every file, runs all detectors, and builds the import map. Typical repositories finish in under 5 minutes.
4. **Review results** on the Project View page:
   - **Overview tab** — Health score, issue counts by severity, top suggestions.
   - **Analysis tab** — Full list of detected issues grouped by category.
   - **Suggestions tab** — Prioritized refactoring recommendations with previews.
   - **Files tab** — File explorer annotated with per-line issues.
5. **Accept or reject** individual suggestions. Each shows the before/after diff.
6. **Apply changes**:
   - Free users: Copy suggested patches and apply manually.
   - Pro/Team users: Click "Generate PR" to create a pull request with all accepted changes.
7. **Generate documentation** — One-click README, API docs, or architecture docs.
8. **Monitor over time** — Re-run analysis after changes to track health score improvements.

## Safety and Trust

Refract is designed as a read-first, write-never-by-default system:

- **Analysis is read-only.** The engine never modifies your repository without explicit user action.
- **Pull requests, not direct pushes.** When applying changes, Refract creates a PR that you review and merge — it never force-pushes.
- **Suggestions are deterministic.** Every detector produces the same result for the same input. No AI hallucination in the analysis layer.
- **Sandboxed execution.** Analysis runs in isolated Web Workers with no access to the DOM or network. Transform operations run in sandboxed environments.
- **Safety gate.** Before applying any transform, the engine validates syntax correctness, import resolution, and type annotation consistency. Failed validations block the transform.
- **No silent changes.** Every modification is previewed, logged, and attributed. The full before/after diff is visible before acceptance.
- **Rollback support.** PR-based workflow means you can revert any change via standard Git operations.

---

## Privacy and Data

- **Your code stays on your machine.** All parsing, analysis, and issue generation happens client-side in Web Workers. No source code is ever sent to a server.
- **Repository metadata only.** When connected to GitHub/GitLab, only repository metadata (name, branch list, file tree) is fetched — file contents remain local during analysis.
- **No code logging.** We never log, store, or transmit your source code. The analysis engine operates entirely in memory.
- **AI features are opt-in.** If using AI-assisted suggestion generation (e.g., via Claude API), the specific context needed is sent with your explicit consent and clearly labeled.
- **Authentication tokens** are stored securely using Supabase Auth and OAuth best practices. Tokens are never exposed to the client-side analysis pipeline.
- **Supabase backend** stores only project metadata and analysis summaries (issue counts, health scores) — never raw source code or full issue details.
- **Third-party services** — We use Supabase for authentication and data persistence, Upstash for rate limiting, and Vercel for hosting. Each follows industry-standard security practices.
- **GDPR compliant.** You can request deletion of your account and all associated data at any time.

## Best Practices

- **Run analysis early.** Connect your repository as soon as you have a working prototype. Early detection of structural issues prevents comprehension debt from compounding.
- **Focus on High priority issues first.** The priority score accounts for both impact and blast radius — fixing high-priority issues yields the largest quality improvement per unit of effort.
- **Batch related suggestions.** Accepting multiple suggestions in a single PR reduces review overhead and groups logical changes together.
- **Re-analyze after refactoring.** Run a fresh analysis after applying changes to verify improvements and catch any regressions.
- **Use health scores as a trend.** Track the health score over multiple analysis runs to measure progress, not as an absolute quality metric.
- **Configure exclusions.** Exclude generated files, third-party vendored code, and test fixtures to focus analysis on your team's code.
- **Integrate with CI (Team plan).** Run Refract analysis on every PR to catch regressions before they merge.
- **Combine with code review.** Use Refract suggestions as a starting point for code review discussions — they highlight structural issues that manual review might miss.
- **Document as you refactor.** Use the documentation generator alongside refactoring to keep README, API docs, and architecture docs in sync with the codebase.

## FAQ

**What is "comprehension debt"?**
Comprehension debt is the gap between code that works and code that is understood. AI-generated code is particularly prone to this because it optimizes for correctness over readability. Refract measures and helps eliminate this debt.

**Does Refract modify my code without permission?**
No. Analysis is always read-only. Any modification goes through a pull request workflow that you explicitly initiate and review.

**Can I use Refract with JavaScript projects?**
Yes. Refract supports TypeScript and JavaScript files (`.ts`, `.tsx`, `.js`, `.jsx`) via Babel's TypeScript plugin. Pure JavaScript projects work the same way.

**What file types are supported?**
Refract analyzes `.ts`, `.tsx`, `.js`, and `.jsx` files. Other file types are skipped during analysis.

**How long does analysis take?**
Typical repositories (under 10,000 files) complete in under 5 minutes. Incremental re-analysis of small changes takes under 30 seconds. Performance depends on file count, not file size — parsing is streaming and memory-efficient.

**Does Refract work with monorepos?**
Yes. Refract treats the repository as a flat file system for import resolution. Monorepo structures with relative imports work correctly.

**What happens if parsing fails?**
Files that fail to parse are skipped and logged. The analysis continues with all other files. Parse errors are reported separately so you can fix and re-run.

**Can I add custom detectors?**
Currently, Refract ships with a fixed detector suite. Custom detector support is on the roadmap for V2.

**Is Refract open source?**
Refract is proprietary software. A free tier is available for individual developers. Pro and Team plans unlock automated refactoring, team collaboration, and CI/CD integration.

**How do I cancel my subscription?**
You can cancel anytime from the Settings page. Your data remains accessible until the end of the billing period. After that, it is retained for 30 days before deletion.

## Getting Started

### Prerequisites
- A GitHub or GitLab account with repositories you want to analyze
- A modern web browser (Chrome, Firefox, Safari, or Edge)

### Quick Start

1. **Visit the app** at [https://refract.dev](https://refract.dev) (or your self-hosted instance).
2. **Sign in** by clicking "Sign In" and authorizing via GitHub or GitLab OAuth.
3. **Connect a repository**:
   - Navigate to the Repositories page (`/repos`).
   - Click "Connect Repository" and select a repository from your account.
   - Choose the branch to analyze (default: `main` or `master`).
4. **Run your first analysis** — The analysis starts automatically after connecting. You'll see progress as each file is parsed and scanned.
5. **Review your results** — Once analysis completes, go to the Projects page (`/projects`) and click on your repository to see:
   - A health score (0–100) on the Overview tab
   - Individual issues on the Analysis tab
   - Prioritized suggestions on the Suggestions tab
6. **Accept a suggestion** — Click a suggestion to see the before/after diff, then accept or reject it.
7. **Generate a PR (Pro/Team)** — Select multiple accepted suggestions and click "Generate PR" to create a pull request on your repository.
8. **Generate documentation** — Click "Generate Documentation" on the Documentation tab to create or update README and API docs.

### Self-hosting

For self-hosted deployments, see the `docs/` directory for infrastructure setup, environment configuration, and Vercel deployment guides. The application requires:
- Node.js 18+
- Supabase project (for auth and storage)
- Upstash Redis (for rate limiting)
- Vercel or Node.js hosting

### Configuration

Key environment variables (see `.env.example`):
- `VITE_SUPABASE_URL` — Supabase project URL
- `VITE_SUPABASE_ANON_KEY` — Supabase anonymous key
- `UPSTASH_REDIS_REST_URL` — Upstash Redis URL (for rate limiting)
- `GROQ_API_KEY` — Groq SDK key (for AI features)
